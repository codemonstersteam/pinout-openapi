# План: обработка `$ref` в сравнении схем

Корректировка к Фазе 1, уточняет `compareSchemas` среза [`01-validate-contract`](./slices/01-validate-contract.md).
Исходный intent — [`../intent-ref-tun.md`](../intent-ref-tun.md). **Только план, не код.**

## Базовые решения

`kin-openapi` закрывает бóльшую часть резолва — план не дублирует библиотеку:

- **Локальные `$ref`** (`#/components/...`) разрешает парсер при чтении. Свой резолвер не пишем, сравнение идёт по `schema.Value` — inline и local-ref неотличимы в обходе.
- **Рекурсия** приходит как **циклический граф указателей** (`Value` ссылается назад). Наивный обход зависнет → нужен детект цикла: **память посещённых пар** `(consumerSchema, providerSchema)`.
- **Внешние `$ref`** (`./common.yaml#/X`, URL): `IsExternalRefsAllowed=false` → загрузчик падает на внешнем ref. MVP-поведение — **hard-fail `SPEC_PARSE_ERROR` (exit 3)**. Это громкий видимый отказ, не маскировка под «совместимо» (требование intent выполнено).

Результат сравнения остаётся **`bool`** (`COMPATIBLE/INCOMPATIBLE`). Модель `messages.md` не меняем.

## 1. Шаг разведки (гейт усложнения)

Цель — решить, хватает ли лин-варианта, по факту реальных спек.

**Что проверить:**
1. `contract-tests.yaml` — куда указывают `spec_path`/`spec_url`; достижима ли спека поставщика.
2. На реальной паре (фетч провайдера, иначе репрезентативная публичная OpenAPI + фикстуры): есть ли `$ref`; доля локальных vs внешних; есть ли рекурсия.
3. Поведение `kin-openapi` на внешнем ref при `IsExternalRefsAllowed=false` (падает / оставляет nil) и версия API обхода (`Paths.Map()`, `Type` как `*Types` в 3.1).

**Как влияет:**
- внешних ref нет → лин-вариант финальный, ничего не усложняем;
- внешние ref **частые И нужна частичная валидация** вместо отказа → только тогда вводим `NOT_VERIFIED` (см. «Отложено»);
- рекурсии нет → слайс C остаётся защитой (память пар), тестовый вес ниже.

**Артефакт:** таблица «вид ref → встречается? → пример» + фикстуры в `testdata/`.

## 2. Инкременты (вертикальные слайсы)

### Slice A — сравнение схем (фундамент)
- **Делает:** рекурсивный обход двух развёрнутых схем по required-полям и типам (через `schema.Value` — локальные ref прозрачны).
- **Вход/выход:** две схемы → `bool` (`COMPATIBLE/INCOMPATIBLE`) + путь несовпадения.
- **Тест:** happy; несовпадение типа; отсутствует required-поле; вложенный объект. **+ регрессия:** «ref-версия ≡ inline-версия» одной схемы дают одинаковый вердикт (доказывает прозрачность local-ref — отдельного слайса не требует).

### Slice C — детект цикла (терминация на рекурсии)
- **Делает:** добавляет память посещённых пар `visited[(ptrC, ptrP)]`; повторная пара = уже сравнивается выше, не уходит в цикл.
- **Вход/выход:** само-ссылающаяся схема (`Node{children:[Node]}`) → терминируется с `bool`.
- **Тест:** рекурсивная пара **обязана** завершиться (таймаут-гард); совместимая рекурсия → `COMPATIBLE`; несовместимость во вложении → `INCOMPATIBLE` с верным путём; асимметрия (потребитель рекурсивен, поставщик нет).

## 3. Зависимости и первый шаг

```
Разведка → A → C
```
- **Первый:** разведка (решает, нужен ли вообще объём сверх A+C).
- **A — фундамент**, **C** надстраивает обход A детектом цикла.

## 4. Осознанно НЕ делаем (отложено)

- **`NOT_VERIFIED` (трёхзначный исход) и загрузка внешних ref.** Включаем **только если** разведка покажет частые внешние ref + потребность в частичной валидации. До этого внешний ref = `SPEC_PARSE_ERROR`. Триггер включения зафиксирован здесь — не делаем «на всякий случай».
- **Лимит глубины как источник статуса.** Память пар уже терминирует на конечных схемах; отдельный `maxDepth→NOT_VERIFIED` порождает ложные срабатывания. Максимум — panic-guard от багов, без выдачи статуса.
- `$ref` на не-schema компоненты сверх того, что разворачивает парсер; `allOf/oneOf/anyOf`, enum-сужение, `format` (out-of-scope `compareSchemas`, см. `messages.md`).

## 5. Точки риска → как ловит тест

| # | Риск | Тест-ловушка |
|---|---|---|
| R1 | Циклический граф → бесконечная рекурсия | рекурсивная фикстура с обязательной терминацией (таймаут-гард) |
| R2 | Ключ памяти посещённых неверный → ложное «уже сравнили» прячет несовместимость, либо не терминирует | две разные рекурсивные пары в одном сравнении; асимметричная рекурсия |
| R3 | Внешний ref молча проходит как совместимый | фикстура с внешним ref → `SPEC_PARSE_ERROR`/exit 3, не `COMPATIBLE` |
| R4 | Поведение парсера на внешнем ref version-зависимо | тест на спеке с внешним ref: прогон не виснет, отдаёт exit 3; проверка конфига загрузчика |

## 6. DoD задачи

- `compareSchemas` обрабатывает inline, локальный ref и рекурсию **без зависания**; внешний ref → `SPEC_PARSE_ERROR` (exit 3), не маскируется.
- Юнит-тесты A и C зелёные, включая тест терминации (C) и регрессию ref≡inline.
- Таблица разведки заполнена; фикстуры в `testdata/`; решение по `NOT_VERIFIED` зафиксировано (включён / отложен с условием).
- `gofmt`, `go vet`, `go test ./...` — зелёные.
