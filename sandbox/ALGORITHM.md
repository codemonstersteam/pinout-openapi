# Алгоритм проверки — функциональный разбор

Простыми словами: **из стаба потребителя восстанавливаем маленький кусок OpenAPI (что он шлёт и что читает),
и сверяем этот кусок со спекой поставщика — поле-в-поле.** Никакого «прогона» запросов, чистая функция над
двумя документами. Ниже — та же логика как композиция чистых функций (ровно то, что делает `check.mjs`).

## Вход и выход

```
check :: (consumedContract, providerSpec) -> { compatible: Bool, errors: [Error] }
```

- `providerSpec` — OpenAPI поставщика (источник истины).
- `consumedContract` — восстановленная из стаба форма ожидания потребителя.
- выход — вердикт + список нарушений (пусто ⇒ совместимо).

## Шаг 1. reconstruct — «восстановить OpenAPI-фрагмент из стаба»

Стаб — это конкретные ПРИМЕРЫ (запрос `{from,to,amount:500}`, ответ `{transferId,status}`). Из примера
выводим ФОРМУ: имя поля → тип. Это и есть «восстановленный кусок OpenAPI» — по операции: что потребитель
**шлёт** (`sends`) и что **читает** (`reads`).

```
reconstruct :: stub -> [ { path, method, sends: {field:type}, reads: {field:type} } ]

inferType(value) = целое → "integer" | дробное → "number" | массив → "array" | иначе typeof
shapeOf(example) = { каждое поле примера ↦ inferType(значение) }
```

> Почему из примера, а не «взять схему потребителя»? Потому что у реального потребителя **нет** отдельной
> «ожидаемой схемы поставщика» — его ожидание уже лежит в стабах компонентных тестов. Мы его оттуда
> **достаём**, а не просим написать заново.

## Шаг 2. providerOp — вынуть схему операции из спеки поставщика

```
providerOp :: (spec, path, method) -> { requestRequired, requestProps, responseProps } | null
```

Навигация по стандартному OpenAPI: `paths[path][method]` → `requestBody` схема и `responses.200` схема.
Нет операции → `null` (поставщик её не предоставляет). В проде этот разбор + резолв `$ref` делает
`kin-openapi`; здесь — `js-yaml` грузит спеку, дальше прямая навигация по дереву.

## Шаг 3. compareOp — сверка одной операции (ядро)

Три правила, каждое — простая проверка вхождения множеств/типов:

```
compareOp :: (consumedOp, providerSpec) -> [Error]
```

| Что сверяем | Правило | Направление | Ловит |
|---|---|---|---|
| операция есть у поставщика | `path+method` найдены | — | удаление операции |
| **request** | всё **обязательное** у поставщика ⊆ то, что потребитель **шлёт** | контравариантно | новое обязательное поле у поставщика |
| **response** | всё, что потребитель **читает** ⊆ то, что поставщик **отдаёт** | ковариантно | **удаление поля из ответа** |
| **типы** | у общих полей тип поставщика = тип, что ждёт потребитель | — | type-drift (`integer`→`string`) |

Формально ядро — два вложения множеств:

```
requires(provider) ⊆ sends(consumer)     -- контравариантность запроса
reads(consumer)     ⊆ provides(provider)  -- ковариантность ответа
```

> **Вот ключ, почему не «валидировать пример схемой поставщика».** На открытой схеме (`additionalProperties`
> по умолчанию разрешены) пример-ответ потребителя, содержащий убранное поле, провалидируется как «поле
> лишнее, но ок» — и удаление НЕ поймается. Мы же проверяем обратное вложение — `reads ⊆ provides` — то есть
> *«каждое поле, что потребитель читает, ЕСТЬ ли у поставщика»*. Убрали `currency` → его нет у поставщика →
> ошибка. Это ровно интуиция «поставщик убрал поле, а стаб его ждёт — это ошибка».

## Шаг 4. check — свёртка по всем операциям

```
check(consumed, spec) =
  errors = concatMap (op -> compareOp(op, spec)) consumed
  { compatible: errors == [], errors }
```

Чистая функция: те же входы → тот же вердикт. Детерминированно, годна для pre-merge гейта в CI.

## Соответствие продовому инструменту

| Песочница (`check.mjs`, node) | Прод (`pinout-openapi`, Go) |
|---|---|
| `reconstruct` из YAML-стаба | `consumed-contract` из E-harness (скилл `component-tests`), с provenance |
| прямая навигация по спеке (`js-yaml`) | `kin-openapi`: parse + резолв `$ref` + валидация схем |
| `inferType` из примера | типы уже в schema-shaped `consumed-contract` |
| проверка вхождения/типов вручную | рекурсивный субтайпинг схем (вложенность/enum/format/nullable даром) |
| таблица в stdout | `Report` в общем канон-JSON + exit `0/1/2/3` |

Песочница доказывает **логику постановки**; прод переносит её на честные библиотеки и глубину схем.
