# 01 — Журнал решений проектирования

Хронология ключевых решений этапа проектирования MVP `validate-contract`. Каждое: контекст → выбор → отвергнутые альтернативы → причина. Даты — 2026-06.

---

## D1 · Природа MVP — чистая функция spec-vs-spec

- **Выбор:** инструмент сравнивает две спеки и всё; конформность сервиса своей спеке и семантику использования контракта обеспечивает слой методологии (компонентные тесты потребителя).
- **Альтернативы:** поднимать contract-true заглушки и гонять тесты внутри инструмента.
- **Почему:** разделение слоёв — инструмент в CI должен быть быстрым и детерминированным; генерация заглушек/сценариев из спеки поставщика вынесена в скилл `component-tests` (эпик E4). Симметрия с `pinout-asyncapi`.

## D2 · Парсер — `kin-openapi` (honest reuse)

- **Выбор:** зрелая библиотека для парсинга и резолва OpenAPI 3.x.
- **Альтернативы:** свой парсер/валидатор схем.
- **Почему:** не переизобретаем валидацию схем; уникальная часть pinout — оркестрация пары consumer↔provider, не разбор формата.

## D3 · Канон формата отчёта определён здесь

- **Выбор:** общий JSON-формат экосистемы (`schema_version`, `validator`, `interaction`, `consumer/provider`, `compatible`, `verdicts[]`, `generated_at`) фиксируется в `pinout-openapi` (`docs/report-format.md`).
- **Альтернативы:** определить в async (E0) или в netlist (E2).
- **Почему:** решение оператора; E1 первый даёт второй валидатор и фиксирует формат, под который подстраивается async и который потребляет netlist.

## D4 · Граница `$ref` — резолв на IO

- **Выбор:** все `$ref` резолвит `SpecClient.Fetch` (IO); чистая логика `compareSchemas` работает на развёрнутых ($ref-free) схемах.
- **Альтернативы:** резолвить ссылки внутри логики сравнения.
- **Почему:** держит логику чистой и простой; убирает двойную обработку `$ref`. (Ревью планировщика, разрыв №1.)

## D5 · Разделение `Report` / `ReportDTO` + инъекция `Clock`

- **Выбор:** `ValidateOperations` отдаёт чистый `Report` (без I/O-полей); `ReportWriter` строит `ReportDTO` (канон) через `ToReportDTO(..., Clock.Now)`.
- **Альтернативы:** один обогащённый `Report` с `generated_at`/`spec_ref` внутри; `time.Now()` в логике.
- **Почему:** `generated_at` — это часы (I/O); вызов из логики нарушил бы изоляцию и детерминизм тестов. Заявленный «маппинг 1:1» на канон был неполон. (Ревью, разрывы №2, №3.)

## D6 · `CONSUMER_OPERATION_NOT_FOUND` — антецедент `NewContractValidate`

- **Выбор:** «операция из конфига отсутствует в спеке самого потребителя» — ошибка целостности конфига; проверяется в конструкторе `NewContractValidate`, коротит трубу до сравнения → **exit 2**.
- **Альтернативы:** обрабатывать внутри `ValidateOperations`.
- **Почему:** `ValidateOperations` возвращает `Report` (успех) — из него нельзя естественно получить exit 2. Поднятие в антецедент согласует exit-код и оставляет `ValidateOperations` только про совместимость с поставщиком (exit 0/1). Соответствует «конструкторы вместо guard». (Согласовано при сверке плана.)

## D7 · Обработка `$ref` — лин-вариант, без оверинжа

- **Выбор:** слайсы `разведка → A (сравнение, local-ref прозрачны) → C (детект цикла памятью пар)`; внешний `$ref` → `SPEC_PARSE_ERROR` (exit 3, громкий отказ). Результат сравнения остаётся `bool`.
- **Альтернативы:** трёхзначный исход `COMPATIBLE/INCOMPATIBLE/NOT_VERIFIED` с кастомным загрузчиком внешних ref; слайс B как отдельная единица; `maxDepth → NOT_VERIFIED`.
- **Почему:** `kin-openapi` сам резолвит локальные ref (B бесплатен) и падает на внешних при `IsExternalRefsAllowed=false` (отказ ≠ маскировка под «совместимо» — требование intent выполнено). Трёхзначная модель и загрузка внешних ref отложены с явным триггером включения (см. `ref-handling.md`). Память пар сама терминирует — лимит глубины как источник статуса лишний.

## D8 · Один срез

- **Выбор:** MVP = один вертикальный срез `validate-contract` (вход CLI `validate`).
- **Почему:** `version`/`info` тривиальны (без алгоритма), вне пакета проектирования.

## D9 · Концептуальный дизайн в нотации C4 (spike)

- **Выбор:** зафиксировать дизайн как C4 на Mermaid: C1 (System Context экосистемы) — в концепте `pinout/README.md`; C2 (Container) + C3 (Component = дерево модулей среза) — в `docs/design/contract-validate/c4.md`. C4 (код) не рисуем — это сигнатуры `impl-brief-01.md`.
- **Альтернативы:** только ASCII-дерево модулей; PlantUML/внешний рендер.
- **Почему:** Mermaid рендерится в GitHub нативно (включая типы C4), без плагинов — диаграмма живёт рядом с кодом и не протухает. Статус — spike по бэклог-пункту скилла `program-design` (см. ниже); C3 один-в-один отражает дерево модулей `slices/01`.

## Состояние и гейт

Пакет проектирования согласован (граф контрактов сходится, 7 Gherkin-сценариев имеют узлы, юнит-N точные). Подготовлен `impl-brief-01.md`. **Реализация не начата** — стартует только после handoff-аппрува оператора в `docs/design/contract-validate/backlog.md`.

## Известные непокрытые риски

Зафиксированы в `docs/risk-coverage.md` (секция границ): `servers`/base-path, `security`, заголовки ответа, required-ность ответа, `additionalProperties`/`nullable`, дрейф ручного списка операций в конфиге — кандидаты в пост-MVP.
