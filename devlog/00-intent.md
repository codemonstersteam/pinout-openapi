# 00 — Намерение

## Что строим

**pinout-openapi** — CLI-валидатор синхронных контрактов OpenAPI. По `contract-tests.yaml` сверяет, совместим ли потребитель с master-OpenAPI поставщика, и отдаёт вердикт (exit code) + канонический JSON-отчёт. Эпик **E1** экосистемы [pinout](../../pinout/README.md), симметричен `pinout-asyncapi`.

Стек: Go; парсер `kin-openapi`; CLI на `cobra`; конфиг — YAML.

## Природа

MVP — **чистая функция сравнения двух спек**: `consumer OpenAPI` vs `provider master OpenAPI`. Без подъёма заглушек и прогона тестов (это слой методологии в репозитории потребителя).

## Зачем этот devlog

Фиксируем процесс проектирования: ключевые решения, рассмотренные альтернативы и причины выбора — то, чего нет в самих дизайн-документах (они описывают «как», devlog — «почему»).

## Что умеет (MVP)

- Прочитать `contract-tests.yaml`, загрузить две спеки (файл/URL).
- Для каждой заявленной операции (path+method) найти её у поставщика и сверить request / response / коды / content-type / схемы (рекурсивно).
- Выдать exit code `0/1/2/3` и JSON-отчёт в общем формате экосистемы.

## CLI

```
validate <contract-tests.yaml>
# exit: 0 совместимо · 1 несовместимо · 2 конфиг · 3 спека
```
